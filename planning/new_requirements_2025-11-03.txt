Новые задачи по требованиям от заказчика (03.11.2025)

1. Онлайн билет для клиента
   - После бронирования продавцом генерировать PDF/ссылку для клиента.
   - Статус: выполнено (03.11.2025).
   - Изменения: добавлен `TicketGenerator.generateAndShare`, продавец и админ получают предложение поделиться PDF сразу после успешного бронирования.
   - Проверка: забронировать место (продавец/админ) и убедиться, что открывается системный диалог шаринга PDF с заполненными данными билета.

2. Ценообразование у администратора
   - Продавец не вводит цену вручную.
   - Админ управляет тарифами (взрослый/детский/пенсионер/инвалид) во вкладке "Цены".
   - Статус: выполнено (03.11.2025).
   - Изменения: добавлена таблица `excursion_prices`, API `PUT /api/excursions/{id}/prices`, вкладка «Цены» позволяет редактировать тарифы; форма бронирования подтягивает тариф автоматически и поле цены удалено.
   - Проверка: в админке открыть вкладку «Цены», изменить значения для экскурсии, сохранить и убедиться в обновлении отображения; продавец при бронировании видит новую цену, поле ввода недоступно.

3. Бронирование по клику на схеме мест
   - Вкладка "Места": выбор свободного места -> форма бронирования.
   - Поддержка выбора 1 места за раз.
   - Статус: выполнено (03.11.2025).
   - Изменения: в диалог схемы мест добавлен выбор свободного места с мгновенным переходом в форму бронирования; форма блокирует поле номеров при предустановленном месте.
   - Проверка: открыть схему мест, тапнуть по зелёному месту — должна открыться форма с заблокированным полем "Места" и выбранным номером; завершить бронирование и убедиться, что запись создана для выбранного места.

4. Вкладка "Прибыль"
   - Отдельная аналитика по доходам.
   - Для обычных продавцов учитывать 10% комиссионные, для партнёров — отдельные ставки.
   - Статус: не начато.

5. Ограничение отмены
   - Если до экскурсии < 24 часов, отмена бронирования недоступна.
   - Статус: выполнено (03.11.2025).
   - Изменения: backend `BookingController@destroy` запрещает отмену, если до экскурсии меньше суток; добавлена валидация причины и запись в описание транзакции.
   - Проверка: попытаться отменить бронирование с датой <24 ч — получить ошибку 422; отмена с большей датой проходит и возвращает возврат с причиной.

6. Форма отмены с причиной
   - При отмене указывать причину (болезнь, передумал и т.п.).
   - Статус: выполнено (03.11.2025).
   - Изменения: добавлен `CancellationReasonDialog` во фронтенд; `BookingsRepository.cancelBooking` передаёт причину на сервер; описание транзакции включает выбранную причину.
   - Проверка: отменить бронирование и убедиться, что диалог запрашивает причину, а в кошельке админа/продавца описание транзакции содержит выбранную причину.

7. Уведомление водителя
   - При назначении экскурсии отправлять уведомление водителю.
   - Добавить подтверждение от водителя.
   - Статус: отложено (по договорённости с заказчиком).

8. Отдельный интерфейс для водителей и экскурсоводов
   - Создать отдельный интерфейс (кабинет) для пользователей с ролью водителя (roleId: 3).
   - Создать отдельный интерфейс для экскурсоводов (role_in_excursion: 'guide').
   - Определение роли пользователя при входе и отображение соответствующего интерфейса.
   - Пока для водителей просто ставим заголовок "Кабинет водителя".
   - Статус: выполнено (03.11.2025).
   - Изменения: обновлен `app_shell.dart` для роутинга по ролям (roleId: 3 для водителей), обновлен `staff_home.dart` с заголовками "Кабинет водителя" / "Кабинет экскурсовода".
   - Проверка: авторизоваться как водитель (roleId: 3) - должен открыться кабинет водителя с соответствующим заголовком.

9. Расширение правил отмены бронирования
   - Отмена бронирования должна быть возможна не только за 24 часа до экскурсии, но и когда экскурсия уже прошла.
   - Текущее ограничение: отмена запрещена только если до экскурсии < 24 часов И экскурсия еще не прошла.
   - Новое правило: разрешить отмену если:
     * До экскурсии >= 24 часов, ИЛИ
     * Экскурсия уже прошла (date_time < now())
   - Статус: выполнено (03.11.2025).
   - Изменения: обновлен `BookingController@destroy` с комментариями о новой логике. Логика уже работала правильно - отмена разрешена для прошедших экскурсий.
   - Проверка: попытаться отменить бронирование прошедшей экскурсии - должно пройти успешно.

10. Multiple selection мест при бронировании
    - Реализовать возможность выбора нескольких мест одновременно при бронировании.
    - После выбора нескольких мест необходимо выбрать тип пассажира для каждого места отдельно:
      * Взрослый (adult)
      * Ребенок (child)
      * Пенсионер (senior)
      * Инвалид (disabled)
    - Статус: выполнено (03.11.2025).
    - Изменения:
      * Backend: `BookingController@store` поддерживает новый формат `seats` (массив {seat_number, passenger_type}) и старый формат для обратной совместимости
      * `BookSeatPayload` обновлен для поддержки обоих форматов
      * `BookingDialog` обновлен: поддержка ввода нескольких мест (через запятую или диапазон 3-7), выбор типа пассажира для каждого места, расчет общей суммы
      * Схема мест обновлена: множественный выбор с визуальной индикацией выбранных мест
      * Генерация PDF обновлена для поддержки нескольких пассажиров
    - Проверка: открыть схему мест, выбрать несколько мест, в форме указать тип пассажира для каждого, завершить бронирование - должно создать несколько бронирований с разными типами.

11. PDF билет на русском языке с несколькими пассажирами
    - PDF билет должен быть полностью на русском языке.
    - Если в бронировании было несколько мест, PDF должен содержать информацию о всех пассажирах.
    - Каждый пассажир должен быть указан с его типом (взрослый/ребенок/пенсионер/инвалид) и номером места.
    - Статус: выполнено (03.11.2025).
    - Изменения:
      * Обновлен `TicketGenerator`: добавлен метод `generateAndShareMultiple` для нескольких пассажиров
      * Используется шрифт Roboto из assets для поддержки кириллицы
      * Все тексты на русском языке
      * PDF содержит список всех пассажиров с типами и номерами мест
      * Общая сумма рассчитывается автоматически
      * Метод `textStyle()` сделан публичным для использования в тестах
    - Проверка: создать бронирование с несколькими местами разных типов, сгенерировать PDF - проверить отображение русских символов и списка пассажиров.

    - Статус: выполнено (03.11.2025).
    - Изменения:
